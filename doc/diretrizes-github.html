02

CONTRIBUIÇÃO INDIVIDUAL

O commit precisa apontar para a pessoa certa.

O gráfico Contributors considera commits da branch padrão e associa o autor pelo e-mail armazenado no objeto Git.

1

Autor

Nome e e-mail configurados antes do commit.

git config user.namegit config user.email
2

Commit

Mudança pequena, coerente e com mensagem objetiva.

git add caminho/do/arquivogit commit -m "tipo: resumo"
3

Main

O commit precisa chegar à branch padrão para aparecer na métrica.

git pull --ff-onlygit push origin main
Não compartilhar autoria

Se uma pessoa criar o commit por outra, o GitHub atribuirá a contribuição ao autor/e-mail registrado — ainda que o arquivo tenha sido produzido por outro integrante. Cada estudante deve revisar e commitar sua própria entrega.

Padrão recomendado de mensagens

feat:nova funcionalidade ou aula implementada
docs:documentação, relatório ou texto técnico
fix:correção de comportamento ou conteúdo
test:ensaio, validação ou caso de teste
refactor:reorganização sem mudar o resultado
03

ACOMPANHAMENTO TÉCNICO

Entregas com responsável, evidência e validação.

O quadro organiza o trabalho já adotado pelo grupo sem impor uma metodologia externa ao projeto.

01ESCOPO

Definir o entregável técnico.

Identificar a aula, os arquivos envolvidos e o comportamento esperado antes da alteração.

02AUTORIA

Registrar quem realizou o trabalho.

O integrante responsável revisa os próprios arquivos e cria o commit com nome e e-mail corretos.

03EVIDÊNCIA

Manter o resultado reproduzível.

Notebooks executados, testes, cenários do simulador e documentação acompanham a implementação.

04VALIDAÇÃO

Conferir conteúdo e integração.

O grupo verifica lógica, links, nomenclatura das variáveis e coerência com a planta envasadora.

05PUBLICAÇÃO

Integrar somente uma versão conferida.

A alteração validada chega à branch principal com mensagem objetiva e permanece identificável no histórico do repositório.

04

CHECKLIST DE ENTREGA

Antes de publicar uma alteração.

Um fluxo curto reduz conflitos, commits atribuídos incorretamente e arquivos sem validação.

  1. 01

    Sincronizar

    Atualizar a cópia local e confirmar que não existem alterações inesperadas.

  2. 02

    Validar autoria

    Conferir nome e e-mail Git antes de criar o commit.

  3. 03

    Revisar arquivos

    Executar notebooks, abrir o portal e conferir links e conteúdo.

  4. 04

    Adicionar explicitamente

    Selecionar somente os arquivos da entrega atual.

  5. 05

    Commitar e enviar

    Usar uma mensagem convencional e confirmar a atualização da main remota.
